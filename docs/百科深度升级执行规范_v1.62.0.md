# 百科深度升级执行规范（v1.62.0）

更新时间：2026-02-23

## 1. 核心目标

让用户不跳转外站，仅依靠百科即可完成：

1. 行业认知
2. 选岗决策
3. 投递准备
4. 笔面试训练
5. 转岗与成长规划

## 2. 全建议落地矩阵（v1/v2/v3合并）

- 建议A：先补岗位树，再补题库。
  - 落地方式：扩容任务保持“岗位缺口优先”，题库补深随后执行。
- 建议B：职业决策六件套全岗位覆盖。
  - 落地方式：新增六件套覆盖率门禁与行业零覆盖监控。
- 建议C：题量从行业统一改为岗位分层。
  - 落地方式：core/mainstream/longtail 分层题量目标（14/10/8）并入门禁。
- 建议D：题库由题目集合升级为训练系统。
  - 落地方式：强制场景桶覆盖（业务/流程/失败/协同/取舍）与追问复用率监控。
- 建议E：增加语义去重，而非仅字面去重。
  - 落地方式：新增高频追问语义模板复用率指标（资源减半/优先级重排类）。
- 建议F：提升平台字段可信度（observed优先于proxy）。
  - 落地方式：新增 role_observed_sample 占比门禁，并记录平台可访问性与留空字段。
- 建议G：提升官方题占比，核心岗更高。
  - 落地方式：新增 overall/core 官方题占比门禁。
- 建议H：平台受限时允许留空但必须可回填。
  - 落地方式：新增不可抓取日志、缺失字段、检索路径、预计回填时间。

## 3. 岗位画像强制字段（职业决策六件套）

每个岗位必须具备：

1. `career_outlook_3to5_year`
2. `typical_work_week`
3. `growth_path_1to3_year`（并补0-1/3-5描述）
4. `switch_directions`（至少3个方向+切换成本）
5. `role_readiness_floor` / 入门门槛证据
6. `prepare_180d_plan`

## 4. 题库训练系统要求

- 分层题量目标：
  - 核心岗：14-20
  - 主流岗：10-14
  - 长尾岗：8-10
- 每岗场景桶至少5类：
  - `business_scenario`
  - `system_process`
  - `failure_review`
  - `cross_team_collaboration`
  - `metric_tradeoff`
- 每题必须含评分维度、rubric、追问链、扣分点、强弱答案信号。

## 5. 平台受限留空规范（BOSS/小红书）

允许留空，不允许伪造。留空时必须写入：

1. 缺失字段列表
2. 检索入口与查询词
3. 检索时间（绝对日期）
4. 无法抓取原因（如404/风控/登录限制）
5. 预计回填时间

必填可留空字段：

- 城市分布
- 薪资区间P25/P50/P75
- 发布时间
- 批次/轮次
- 帖子ID/链接
- 样本量
- 截图时间

## 6. 信息源分层

- L1：政策/监管/企业官方岗位页（主证据）
- L2：BOSS/智联/51job/猎聘/地方统计（交叉验证）
- L3：牛客/小红书（训练补充，必须标注回忆样本）

强结论（趋势/薪酬/政策）必须 `L1+L2` 双证据。

## 7. v1.62门禁阈值

- 六件套覆盖率：`>= 60%`
- 场景桶覆盖：每岗 `>=5`，未达标命中数 `<=0`
- `role_observed_sample` 占比：`>= 60%`
- 官方题占比（overall）：`>= 35%`
- 官方题占比（core）：`>= 50%`
- 追问语义复用（资源减半类）：`<= 20%`
- 岗位文本同质化目标：`<= 65%`（分阶段收紧）

## 8. 发布前清单

1. 岗位缺口是否优先补齐。
2. 六件套是否完整。
3. 分层题量与场景桶是否达标。
4. 平台缺口是否按规范留空并可回填。
5. 来源是否满足L1/L2/L3边界。
6. 语义复用是否低于阈值。
