# 信息源分级与抓取规范（v1.25.0）

## 1. 证据分级

### 一级证据（优先，结论必须至少1条）
- 政策与制度：
  - 教育部: https://www.moe.gov.cn
  - 人力资源和社会保障部: https://www.mohrss.gov.cn
  - 中国政府网: https://www.gov.cn
  - 国家统计局: https://www.stats.gov.cn
- 就业与公共招聘：
  - 国家大学生就业服务平台（NCSS）: https://www.ncss.cn
  - 中国公共招聘网（人社部）: http://job.mohrss.gov.cn
- 招录考试：
  - 国家公务员局: http://www.scs.gov.cn
  - 中国人事考试网: http://www.cpta.com.cn
  - 各省人社厅/考试院官网（公告页优先，避免只挂首页）
- 企业端：
  - 公司校招官网/招聘官网（优先公告页、岗位详情页、宣讲日程页）

### 二级证据（补充，关键结论建议再加1条交叉验证）
- 招聘平台与研究机构原始报告页：
  - 猎聘: https://www.liepin.com
  - 前程无忧（51job）: https://www.51job.com
  - 其他商业平台（智联/BOSS）优先官方报告原页，不使用二次转载新闻作为唯一依据。
- 社区回忆样本：
  - 牛客、校招社区、论坛回忆帖（必须标注“回忆样本/非官方原卷”，并降低证据权重）

## 2. 模块到来源的映射建议

- 政策变化日志：一级证据为主（教育部/人社部/国务院/统计局），二级证据仅用于解释。
- 年度校招时间线：企业校招官网公告页 + 国家平台活动页。
- 岗位画像库：企业JD + NCSS 交叉；社区样本只作能力项补充。
- 行业事件日志：至少“1条官方来源 + 1条二级验证来源”；事件条目写成“事实 + 影响 + 证据链”。
- 薪酬微观观察层：
  - `gov_stat_anchor`：国家统计/地方统计年鉴
  - `jd_posted_range`：企业JD或平台JD
  - `offer_recall`：社区回忆样本（匿名去标识）
- 薪酬估算层：仅用于缺失补位，必须与观察层分开展示。

## 3. 抓取字段（强制）

每条事实记录至少保存以下字段：
- `publish_date`：原文发布日期（新鲜度主口径）
- `source_date`：兼容字段（与 `publish_date` 对齐）
- `accessed_at`：抓取访问时间
- `captured_at`：证据快照入库时间
- `data_period`：数据所属期（如 `2025Q4` / `2025-01~2025-12`）
- `source_id/source_url/source_type`
- `sample_size`（可量化样本时必须填写）

## 4. 质量门槛建议

- 关键结论：至少1条一级证据 + 1条二级交叉验证。
- 事件日志：`min_sample_size_for_verified >= 2`。
- 薪酬：观察层与估算层分开；展示置信区间与证据层级。
- 题库/面经：必须标注真实性标签（official / real_user / curated）。

## 5. 反模式（禁止）

- 只留来源首页，不留具体公告/岗位页。
- 只用新闻转载页替代原始发布页。
- 将抓取日期当作发布日期，导致新鲜度虚高。
- 把用户个性化待填槽位计入百科本体完成度。
