## 2. 模块到来源的映射（执行口径）

- 政策变化日志：至少 1 条一级官方政策源；关键结论再加 1 条二级交叉源。
- 年度校招时间线：企业校招公告页 + NCSS/中国公共招聘网活动页双锚点。
- 从业者访谈/案例复盘：优先公司官方 JD/招聘页；不足时补 `real_user_recall` 并下调置信度。
- 行业事件日志：统一写成 `fact + impact + industry_indicator + evidence_chain`，`chain_level` 目标为 `dual_source`。
- 薪酬模块：
  - 观察层：`gov_stat_anchor` / `jd_posted_range` / `offer_recall` / `commercial_report`
  - 估算层：仅用于缺口补位，必须与观察层分开展示。
- 题库模块：官方样题 > 官方说明 > 回忆题；回忆题必须打 `authenticity_level=real_user`。

## 3. 日期语义（强制）

每条可验证事实保留以下字段：
- `publish_date`：原始发布日期（新鲜度主口径）
- `source_date`：兼容日期字段（与 `publish_date` 对齐）
- `accessed_at`：抓取访问时间
- `captured_at`：入库快照时间
- `data_period`：数据所属期（如 `2025Q4` / `2025-01~2025-12`）

## 4. 质量门槛（v1.26）

- 事件日志：`min_sample_size_for_verified >= 2`，新增条目优先 `chain_level=dual_source`。
- 访谈与案例：每行业建议 `>=3` 条，且至少 1 条使用行业公司官方或行业主管部门来源。
- 来源集中度：目标 `top1 < 7%`、`top5 < 25%`（保留安全余量，避免回退）。
- 个性化字段：`pending_user_fill` 不计入百科本体完成度，单独统计“个性化完善度”。

## 5. 反模式（禁止）

- 只留来源首页，不落到公告/JD详情页。
- 用新闻转载替代原始发布页作为唯一证据。
- 将 `accessed_at/captured_at` 当作 `publish_date` 使用，造成新鲜度虚高。
- 未标注真实性等级就混用回忆样本与官方口径。
