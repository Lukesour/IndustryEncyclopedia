# 百科深度升级执行规范（v1.61.0）

更新时间：2026-02-20

## 1. 目标

让用户不跳转外站，仅依靠百科完成：

1. 行业认知
2. 岗位选择
3. 投递规划
4. 笔面试训练
5. 复盘与转岗决策

## 2. 岗位扩容原则

- 不统一岗位数量，按行业复杂度扩容。
- 先补岗位树，再补题库深度，避免“题多但选岗不全”。
- 校准执行清单基线：`current_roles` 必须与当前库实时一致。
- 每轮发布必须输出：行业岗位缺口、题库缺口、平台字段缺口。

## 3. 题库扩容与分层目标

- 阶段覆盖必须包含：提前批、主批、补录、实习转正。
- 题库采用“可实战”分层目标：
  - 核心岗位：14-20（笔）/14-20（面）
  - 主流岗位：10-14（笔）/10-14（面）
  - 长尾岗位：8-10（笔）/8-10（面）
- 题目必须绑定岗位ID、阶段字段、场景类型。
- 每岗至少覆盖以下场景桶：
  - 业务场景题
  - 系统/流程题
  - 失败复盘题
  - 跨团队协同题
  - 指标取舍题

## 4. 岗位画像深度（职业决策六件套）

每个岗位必须可直接支持职业决策，至少覆盖：

1. 3-5年需求前景与驱动因素
2. 典型工作周节奏（周/月）
3. 成长台阶（0-1年/1-3年/3-5年）
4. 可迁移方向（至少3个）与切换成本
5. 入门门槛（硬技能/项目证据/证书）
6. 准备路线图（90天/180天）

## 5. 面试可执行性门槛

- `star_evidence_template` 填充率：100%
- `common_deduction_points` 填充率：100%
- 每题必须含：
  - 评分维度
  - 评分rubric
  - 追问链
  - 扣分触发点
  - 强弱答案信号

## 6. 平台受限处理（BOSS/小红书）

- 允许留空，不允许伪造。
- 必须保留：缺失原因、检索方式、检索时间、预计回填时间。
- 必填留空位字段：
  - 岗位名称
  - 城市
  - 公司层级
  - 批次/轮次
  - 薪资区间P25/P50/P75
  - 发布时间
  - 来源链接或帖子ID
  - 样本量
  - 截图路径与截图时间

## 7. 信息源分层

- L1（强结论）：政策、监管、企业官方招聘页与岗位详情页。
- L2（交叉验证）：BOSS、智联、51job、猎聘与地方公开统计。
- L3（扩题补充）：牛客、小红书面经，必须标注回忆样本。

## 8. 新增质量门禁（v1.61）

- 岗位文本同质化：`day_in_life/growth/transfer/prep` 语义重复率不得超过阈值。
- 平台占位比例：`completed_with_placeholders` 占比不得超过阈值。
- 关键字段完整率：`star` 与 `deduction` 不达标即拦截。
- 基线漂移：执行清单 `current_roles` 与现库不一致时，不得直接排期。

## 9. 发布前清单

1. 行业岗位数是否达到本轮目标。
2. 每岗位笔面试题量是否达到分层目标。
3. 4阶段是否覆盖。
4. 职业决策六件套是否完整。
5. 平台缺口是否有可追溯检索说明。
6. 来源是否满足 L1/L2/L3 使用边界。
7. 同质化、占位比例、`star/common` 是否达标。
